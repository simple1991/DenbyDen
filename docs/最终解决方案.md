## 🔍 为什么需要所有表的策略？

埋点系统的工作流程：

1. **插入主事件** → `events` 表 ✅（您已有策略）
2. **插入详细信息** → 根据事件类型插入到对应表：
   - `product_exposures` ❓（可能没有策略）
   - `product_clicks` ❓
   - `cart_actions` ❓
   - `email_captures` ❓
   - `page_interactions` ❓
   - `page_dwell_time` ❓

如果步骤 2 失败（相关表没有策略），整个插入过程会失败，即使 `events` 表的插入成功。

## ⚠️ 常见问题

### Q: 为什么 `events` 表有策略但还是 401？

**原因**：
- 插入 `events` 表成功后，还需要插入到相关表
- 如果相关表没有策略，整个事务会失败

**解决**：
- 运行完整修复脚本，为所有表创建策略

### Q: 运行修复脚本后还是 401？

**检查项**：
1. ✅ 所有表是否都有策略？（运行验证脚本确认）
2. ✅ API key 是否正确？（应该是 anon key，JWT token 格式）
3. ✅ 是否重启了开发服务器？
4. ✅ 是否清除了浏览器缓存？

### Q: 如何确认修复成功？

运行以下查询：

```sql
-- 应该返回 7 行，每行代表一个表的 INSERT 策略
SELECT 
    tablename,
    policyname,
    roles
FROM pg_policies 
WHERE tablename IN (
    'events',
    'product_exposures',
    'product_clicks',
    'cart_actions',
    'email_captures',
    'page_interactions',
    'page_dwell_time'
)
AND cmd = 'INSERT'
ORDER BY tablename;
```

应该看到所有 7 个表都有策略，且 `roles` 中包含 `anon`。
