- JWT token 格式
- 通常以 `eyJ` 开头
- 长度较长

**检查方法**：

1. 检查环境变量：

   - 进入 **Settings** → **API**

## 🚨 常见问题

### Q: 策略存在但还是 401？

**可能原因**：
1. API key 不正确
2. 策略的角色配置错误
3. 使用了错误的 key（比如用了 service_role key）

**解决方法**：
- 确认使用的是 **anon/public** key，不是 service_role key
- 检查策略中的 `TO anon` 部分是否正确

### Q: API key 格式 `sb_publishable_xxx` 是什么？

这看起来像是 Supabase 的新格式或者是其他服务的 key。标准 Supabase anon key 应该是 JWT token 格式。

**解决方法**：
- 在 Supabase Dashboard 的 Settings → API 中获取正确的 anon key
- 确保复制的是 **anon/public** key，不是其他 key

### Q: 如何确认策略是否生效？

运行以下 SQL：

```sql
-- 查看 events 表的所有 INSERT 策略
SELECT 
    tablename,
    policyname,
    roles,
    cmd,
    with_check
FROM pg_policies 
WHERE tablename = 'events' 
  AND cmd = 'INSERT';
```

应该看到至少一个策略，且 `roles` 中包含 `anon`。
