# 快速故障排除指南

## 问题诊断流程

如果您遇到 401 Unauthorized 或 RLS 策略错误，请按照以下步骤操作：

### 步骤 1：检查错误类型

**打开浏览器控制台（F12）**，查看具体错误信息：

1. **如果是 `PGRST205` 错误** → 表不存在，请运行 `docs/supabase_schema.sql`
2. **如果是 `42501` 或 `401` 错误** → RLS 策略问题，继续步骤 2

### 步骤 2：检查当前策略状态

1. 打开 Supabase Dashboard
2. 进入 **SQL Editor**
3. 运行 `docs/check_rls_policies.sql` 脚本
4. 查看输出结果

**如果输出为空或策略名称冲突** → 继续步骤 3

### 步骤 3：运行完整修复脚本

1. 在 SQL Editor 中运行 `docs/fix_rls_policies_complete.sql`
2. 等待执行完成
3. 再次运行检查脚本验证

### 步骤 4：验证修复

1. 刷新浏览器页面
2. 检查控制台是否还有错误
3. 如果还有错误，查看具体错误信息

## 常见问题

### Q1: 运行脚本后仍然有 401 错误

**可能原因**：
- 脚本没有完全执行成功
- 策略创建失败但没有报错
- API Key 配置错误

**解决方法**：
1. 在 Supabase Dashboard 中检查是否有 SQL 错误
2. 运行 `check_rls_policies.sql` 查看策略是否真的创建了
3. 检查 `lib/supabase.ts` 中的 API Key 是否正确（应该是 `anon` key）

### Q2: 如何确认使用的是正确的 API Key？

**检查方法**：
1. 打开 Supabase Dashboard
2. 进入 **Settings** → **API**
3. 找到 **anon/public** key
4. 确认 `lib/supabase.ts` 中使用的 key 是否正确

**注意**：必须使用 **anon key**，不要使用 **service_role key**（它会在客户端暴露）

### Q3: 策略创建成功但仍然有权限错误

**可能原因**：
- 策略创建了但角色配置错误
- RLS 启用但策略条件不正确

**解决方法**：
1. 运行检查脚本查看策略详情
2. 确认策略中的 `TO anon` 部分存在
3. 确认 `WITH CHECK (true)` 存在

### Q4: Immersive Translate 错误是什么？

这是浏览器扩展（沉浸式翻译）的问题，**与您的代码无关**，可以忽略。

## 一键修复

如果上述步骤都无效，可以尝试完全重置：

```sql
-- 警告：这会删除所有策略，请谨慎使用

-- 1. 删除所有策略
DO $$
DECLARE
    r RECORD;
BEGIN
    FOR r IN (SELECT tablename FROM pg_tables WHERE schemaname = 'public' AND tablename IN ('events', 'product_exposures', 'product_clicks', 'cart_actions', 'email_captures', 'page_interactions', 'page_dwell_time')) LOOP
        EXECUTE 'DROP POLICY IF EXISTS "' || r.tablename || '_anon_insert" ON ' || quote_ident(r.tablename);
        EXECUTE 'DROP POLICY IF EXISTS "' || r.tablename || '_service_read" ON ' || quote_ident(r.tablename);
    END LOOP;
END $$;

-- 2. 然后运行 fix_rls_policies_complete.sql
```
